Coderabbit included API and MCP server access on every plan

What changed
Coderabbit added a new FAQ entry, "Which plans include the CodeRabbit API and MCP server?", to its pricing page. Its answer states that API and MCP server access is included with every plan, and that each API or MCP call works against whatever features that plan already covers.
The Enterprise plan's own comparison-table line also changed wording: what was labeled "API access and usage metrics" under Enterprise Controls is now "Admin APIs and usage metrics," covering administration of users, seats, roles, audit logs and metrics rather than general API access, which the new FAQ now addresses separately.
Why it matters
For a product leader, this is a packaging signal more than a feature signal: Coderabbit is treating API and MCP access — the hooks a team would use to wire the reviewer into its own CI, agents or internal tools — as baseline plumbing rather than an Enterprise upsell. Admin APIs, covering user, seat, role, audit-log and metrics administration, stay Enterprise-gated, which is a more defensible place to draw an access line than raw API/MCP connectivity.

Common questions
What should we check before writing code against Coderabbit's API or MCP server?
Confirm your org type first: Coderabbit's FAQ says the MCP server only works for cloud-hosted organizations, not a self-hosted CodeRabbit deployment or a self-hosted Git provider — worth checking before you build against it if your org runs self-hosted.
Why did Coderabbit rename Enterprise's 'API access' line to 'Admin APIs'?
Coderabbit hasn't published a stated reason for the rename, and its FAQ only describes what each line now covers, not why the wording changed — so treat it as a clarification rather than a new restriction until the company says otherwise.
Could API or MCP access move behind a paywall again later?
Nothing on Coderabbit's current pricing page or FAQ points to that, but the company has changed its page often enough, including altering add-on and overage pricing within the last 90 days, that it's worth re-reading the FAQ before assuming free access is permanent.
